# Архитектура и технические решения

## Философия разработки

**KISS + Бритва Оккама + YAGNI** — простота, минимализм, никакой спекуляции

- **Минимум абстракций**: не создавай функции/типы "на будущее", только для реальной задачи
- **Явное > неявного**: код читается как инструкция, без скрытой магии
- **Одна ответственность**: функция делает одно, крейт решает одну задачу
- **Прямолинейность**: решение очевидно при чтении → правильно; требует расшифровки → переделай
- **Простота > элегантности**: работающий прямой код лучше "красивого" сложного

## Исходники zstd

Вендорятся в директорию `zstd/lib/` скриптом `zstd/update.ps1`.

Из полного архива zstd берём только нужное:
- `lib/zstd.h`, `lib/zstd_errors.h` — публичный API
- `lib/common/` — базовые примитивы
- `lib/compress/` — компрессия (включая многопоточный zstdmt)
- `lib/decompress/` — декомпрессия

Не нужно и удаляется после скачивания:
- `lib/legacy/` — поддержка форматов до v0.8
- `lib/dictBuilder/` — обучение словарей
- `lib/deprecated/` — устаревший API
- `lib/dll/` — Windows DLL сборка

Текущая версия хранится в `zstd/VERSION`.

## Публичный API

Корень репозитория содержит публичный API для подключения к проектам:

- `zaster.h` — публичный C API: включает заголовки zstd и все модули libzaster
- `zaster.hpp` — C++ враппер: `namespace zaster::` для типов и функций libzaster, `namespace zstd::` для обёрток над zstd API
- `CMakeLists.txt` и аналоги для других языков — готовая инфраструктура подключения

Пользователь подключает репозиторий как подмодуль или скачивает zip — и сразу получает всё необходимое.

### Опция ZASTER_LINK_ZSTD

CMake-опция `ZASTER_LINK_ZSTD` (по умолчанию `ON`) управляет линковкой libzstd:
- `ON` — линкуем `prebuilt/<target>/libzstd.a` (или собираем из исходников)
- `OFF` — пользователь сам линкует свою версию libzstd; заголовки zstd всё равно используются наши

Аналогичная механика реализуется в сборочных конфигурациях других языков (build tags в Go и т.д.).

## Сборка

Компилятор: Clang (кросскомпиляция через `ghcr.io/powertech-center/alpine-cross-clang`).

Многопоточная компрессия активируется флагом `-DZSTD_MULTITHREAD` + `-lpthread` (Linux/macOS) или WinAPI (Windows).

CGo не вызывает Makefile — компилирует `.c` файлы напрямую через директивы `#cgo`.

## Статические библиотеки в `prebuilt/`

Структура: `prebuilt/<таргет>/libzstd.a` и `prebuilt/<таргет>/libzaster.a`.

Стратегия линковки:
1. Есть готовая библиотека для таргета → линкуем её
2. Нет → собираем из исходников на хосте

## Сборка libzaster

Исходники в `lib/`, компилируется в статическую библиотеку `libzaster.a`.

Скрипт сборки: `lib/build.ps1` — использует тот же Docker-образ и те же таргеты что и zstd.

Определения таргетов вынесены в общий файл `zstd/targets.ps1` (dot-sourcing).
Оба скрипта (`zstd/build.ps1` и `lib/build.ps1`) подключают его через `. "$PSScriptRoot/../zstd/targets.ps1"`.

Результат сборки: `prebuilt/<таргет>/libzaster.a`.

## Скрипты инфраструктуры

Пишутся на PowerShell (`.ps1`) — работает на Windows, Linux и macOS.
Все комментарии и строки в скриптах — на английском языке.
